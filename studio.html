    How it works

    1. Pick your reader — X3 (528 × 792), X4 or X4 Pro (480 × 800).
    2. Drop an image — it is resampled with an area-average filter, so no aliasing and no stretched pixels.
    3. Dither to 4 greys — the panel's real palette, so the preview is what the screen draws.
    4. Export the exact panel size — CrossPoint never scales, so one wrong pixel means white borders.

    Connect to your reader

    On the reader: Home → File Transfer → Join Network (or Create Hotspot). The reader shows a URL such as http://192.168.1.102/. Enter the IP here — mDNS (crosspoint.local) only resolves on some networks.

      Putting the file on your reader

      CrossPoint shows a custom sleep screen only when Settings → Display → Sleep Screen is set to Custom (or Cover + Custom). If no valid image is found it silently falls back to the Dark logo — which is why the size and encoding below matter.

      1. Copy the BMP to the card

      • One image: save it as sleep.bmp in the root of the microSD card.
      • A rotating set: put any number of .bmp files in a folder named .sleep (a plain sleep folder also works) at the card root.
      • On macOS the .sleep folder is hidden — press Cmd+Shift+. to show it.
      • Or send it over Wi-Fi from the Send to device tab — no card reader needed.

      2. On the device

      Settings → Display → Sleep Screen → Custom. In CrossPoint 1.5 the setting is under Settings → Display; some builds call the entry Screensaver.

      CrossPoint does not rescale images. A 480 × 800 file on an X3 shows white borders; a phone screenshot is not a valid size either. CrossPoint Studio always writes the panel's exact width and height, and rows are padded to the 4-byte BMP boundary for you.

      Which format?

      • 24-bit BMP — the safest choice. Uncompressed BI_RGB, read by stock firmware and every CrossPoint build.
      • 2-bit BMP — a four-entry greyscale palette. CrossPoint and CrossInk decode it; a twelfth of the size, and noticeably quicker to open on the ESP32.
      • 1-bit BMP — pure black and white for logos and line art.
      • JPG and PNG are not valid custom sleep screens; renaming one to .bmp will not work.

      Dithering and ghosting

      The panel draws four greys. Photos have thousands, so they must be dithered. Tests in the firmware tracker show that dithered images refresh more cleanly than smooth grey gradients, which can leave the previous page ghosting underneath. Floyd–Steinberg is the default for photos; Atkinson holds contrast better on ink drawings and line art.

      Transparent overlays

      CrossPoint 1.6+ (and CrossInk) can draw a see-through overlay instead of a full image: sleep-overlay.png or a folder of them in .sleep-overlay, with sleep screen mode Transparent. A BMP has no alpha, so for per-pixel transparency use a PNG with an alpha channel or a 32-bit BGRA BMP. In this extension, use Fit with a transparent source and export a PNG to keep the cut-out.

      Troubleshooting

      It still shows the CrossPoint logo
      Sleep Screen is not on Custom, the file is not named sleep.bmp in the card root (or inside .sleep), or the encoding is paletted/compressed. Export 24-bit here and try again.
      White borders on all four sides
      The file is not the panel size — usually an X4 file (480 × 800) on an X3 (528 × 792). Pick the right device above and re-export.
      Muddy or blotchy result
      Busy mid-tones collapsing into four levels. Raise contrast, try Ordered 4×4, or use Atkinson for line art.
      "Could not reach …" when sending over Wi-Fi
      Use the IP address rather than crosspoint.local, make sure File Transfer mode is still open, and check both devices are on the same network.
      Upload says "File already exists"
      Enable Replace files with the same name, which sends overwrite=1 and writes via a .part file.

      Privacy

      Conversion runs entirely on your machine. Images never leave the browser unless you explicitly press Send to reader, in which case the BMP goes only to the address you typed. No analytics, no remote servers, no accounts.
